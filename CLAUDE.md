# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Keep this file current

Update CLAUDE.md in the same commit as any change that makes it wrong or incomplete: new or renamed commands, architecture, file responsibilities, network messages, game rules, deployment. Remove statements that are no longer true instead of adding caveats.

## Every change ships with its checks and its record

Do these in the same commit as the change, not afterwards:
1. **Bots play it.** Any change to game functionality (rules, numbers in `sim.js`, buyers, eras, drilling, contracts, truck logic, race or shared-map rules) runs `npm run balance` before the commit. Compare with the previous run: no bankruptcies in the solo scenarios, every buyer keeps a share of revenue, the eras spread over the year, failed contracts stay rare, money grows from the start sum. Fix the balance or state the known deviation in the commit message; never commit a number you have not seen the bots play. UI-only changes skip this.
2. **CLAUDE.md** is updated as described above.
3. **CHANGELOG.md** gets an entry under "Nevydáno" for every player-visible novelty or change (new mechanic, buyer, tool, UI panel, rule, balance change the player will feel), written in Czech from the player's point of view, one or two lines each. Refactors and fixes nobody would notice do not go in. When a feature from `docs/navrh-v2.md` is finished, mark it done there too.

## Working style (token budget)

Follows `docs/claude-code-prirucka.md`; this section is the part Claude applies.
- Terse replies: no preamble, no recap, one line on what changed and where. Show only changed code. At most one clarifying question.

## What this is

"Oil digga" (package name `turmoil-activity`): an oil tycoon that runs as a Discord Activity (solo, a race where everyone plays a copy of the same map, or one shared real-time map). The game is plain browser code with no bundler: `index.html`, `style.css` and classic scripts sharing one global scope (no modules): `ads.js` (ad configuration, global `OIL_ADS`), `sim.js` (game rules, also `require`d by the server), `net.js` (Discord login, lobby, race/shared flow) and one big `script.js` (rendering, input, HUD, sound). A Node server (`server/`, Express + `ws`) serves the game, exchanges the Discord OAuth code and runs the lobby rooms. Only the Discord SDK is bundled (esbuild: `client/discord-sdk.js` -> `dist/discord-sdk.js`, global `OilDiscordSDK`). UI text and code comments are in Czech; keep that. Discord Developer Portal setup (URL mappings, secrets) and Render deployment are in `README.md`.

## Commands

```bash
npm install
cp .env.example .env      # DISCORD_CLIENT_ID / DISCORD_CLIENT_SECRET / PORT; .env is gitignored
npm run dev               # build the SDK bundle, run server/index.js on :3000 with --watch
npm start                 # same without watch (what the host runs)
npm run static            # plain http-server without the backend: no lobby, net.js falls back to solo
npm test                  # node --test test/*.test.js
node test/sim.test.js     # one suite (each test file is a standalone script that exits non-zero on failure)
npm run balance [solo|race3|shared2|...|all]   # bots play whole games over 16 seeds; prints money, $/bbl, buyer shares, era days, contracts
node --check script.js    # syntax check (also sim.js, net.js, server/*.js); there is no lint
```

Tests cover `sim.js`, the lobby rooms and the server-side shared game, not rendering; check visual changes in a browser. After touching any number in `sim.js` (`C`, `RULES`, `BUYERS`, `ERAS`, `ROCKS`) run `npm run balance` and compare with the previous output: no bankruptcies in solo, every buyer gets a share, eras spread over the year, failed contracts stay rare. Lobby without Discord: open `/?user=Alice&room=test` and `/?user=Bob&room=test` in two tabs (guest ids live in `sessionStorage`). Top-level `let`/`const` in `script.js` are reachable from the devtools console; change state through `world`/`doAction`, the other globals are only a mirror:

```js
world.players[myId].money = 9000; doAction({ type: 'buyPlot', plotId: 1 }); isPaused = true;  // freeze the real loop
update(16);        // then step the world yourself (OilSim.step + events + syncFromWorld)
```

Deployment: `render.yaml` (Render blueprint; `DISCORD_CLIENT_SECRET` is set in the Render dashboard). Vercel cannot host the WebSocket server.

## Design direction

Visual and UI work must look hand-crafted and specific to this game, not like a generic AI-generated template. Build on the established art direction instead of introducing a new style:
- Night oil boomtown in the desert: cool moonlight rim light (`MOON_X`) against warm lamps, flares and glowing oil; a 2.5D cut-away diorama; everything on the canvas is custom vector drawing with additive glow (`drawGlow`), no stock images.
- "Print shop and telegraph" on night paper: every UI surface is aged, dim paper caught by lamplight (`--paper`, `--ink`, `--stamp-*` in `style.css`; the canvas uses the same palette as `PAPER_TOP`/`INK`/`INK_RED` and `fillPaper()` in `script.js`). Notifications are telegrams (`notify` -> `.telegram`, text ends with STOP), goals and the race board are a ledger, the event log is telegraph tape, world news and race results are the "Pouštní kurýr" newspaper, the lobby is the land office notice board (claims register, form with pen-crossed checkboxes, rubber-stamp buttons), the clock is a tear-off calendar, the resource bar a torn printed strip, the toolbar an order form, buyer cards and rig/pocket labels paper tags. Only real instruments (the pressure gauge) stay metal.
- Typography: Rye for headlines, signs and stamps; Courier Prime for typed text (telegrams, ledger, newspaper); Barlow Condensed for HUD labels and numbers (also on the canvas). All three are self-hosted with Czech glyphs (`latin-ext` subsets via `unicode-range`).
- Icons: the `ICONS` set in `script.js` (`iconSvg(name)`, inline SVG with `currentColor`); never emoji as UI icons.
- Avoid templated defaults: purple/blue gradient backgrounds, identical rounded cards everywhere, centered "hero" layouts, generic glassmorphism, placeholder copy. Motion should mean something (a strike, a blowout, breaking news), not decorate.
- Every new element gets the same care: lighting consistent with the scene, depth (shadows, parallax, occlusion), readable at the compact HUD size, and checked in a browser screenshot.

## Architecture

**Game rules (`sim.js`, `OilSim`).** One `world` object holds everything for all players: `createWorld({ seed, players, race, shared })`, `act(world, playerId, action)` (the only way to change state; validates everything, because on the shared map actions arrive over the network), `step(world, dt)` (calendar and land tax, market, news, drilling, reservoir, pumping, pressure, trucks, exploration tools; before `world.time.started` only tools run) and `world.events` (sale, strike, blowout, news, ... drained by the caller for sounds and toasts). Per-player state is in `world.players[id]`; plots, rigs (`pipeNetworks`) and trucks have an `owner`. With a `seed` the map is identical for everyone; the market uses `world._market` (seeded, not serialized) and news use `dayRandom` (seed + `time.dayIndex`), so race players get the same headlines on the same day regardless of frame timing. Key mechanics:
- Claims (`createClaims`): 7–9 plots of irregular `width` fill `CLAIM_SPAN` between the side buyers (no fixed plot width; use `plot.width`, `plotCenterX`, `plotAtX`). Each has a `terrain` (`TERRAIN`): `hill` multiplies derrick/silo cost (`buildMult`), `river` makes water injection cheap (`injectMult`), `rock` puts a granite cap under the surface to `plot.rockDepth` (`rockAt` checks it before the strata), `flat` nothing. Price grows with width and terrain.
- Drilling (`stepDrilling`): action `drill` appends a waypoint to the rig's `path` (no steep climbs, `DRILL_MAX_RISE`); the bit advances `network.drilled` px along the path in real time at `DRILL_SPEED × ROCKS[rock].speed`, paying `DRILL_COST_PER_PX × rock.cost` per px (stalls without money) and wearing `network.bit`. `drillState`: `drilling | idle | kick | shut | swap | worn | done`. Rock comes from `world.strata` (`rockAt`, wavy `bounds` + `layers`). `world.hazards` (gas caps sit just above pocket roofs, more often on deep pockets, plus a few free gas pockets and wide water layers in the shallow half): gas → `kick`, the player has `KICK_MS` to `bop` (else blowout with fine and a dead bit); water → `network.waterCut` (`cement` removes it). `bit` swaps the bit, `drillStop` cuts the plan at the bit (`cutPathAtHead`). Entering a pocket polygon (`isSegmentIntersectingPolygon`, not the bounding box) cuts the path there and starts pumping (`network.pocket >= 0` = connected).
- Pockets/reservoir (`stepReservoir`, `stepPumping`): any number of rigs may tap one pocket; each pumps `wellRate = OIL_PER_SECOND × pocketDrive × (1 − waterCutOf)`, drive falls with the fill (`drive0 × fill^DECLINE_EXP`, deeper pockets are richer with higher `drive0`). `inject` turns a rig into a water injector: no production, costs `INJECT_COST_PER_S`, raises `pocket.boost` for every rig on the pocket but slowly raises `pocket.waterCut`. `world.links` connect neighbour pockets; oil flows toward the emptier one. `revealedBy` (georadar, also reveals hazards) and `echo[playerId]` (seismics, drone) keep exploration private. Everything from `docs/navrh-v2.md` is in; the doc keeps the original reasoning.
- Trucks: state machine `idle -> to_rig -> waiting_at_rig | to_company -> to_rig ...`; rig (`findNetworkForTruck`, own rigs that pump or still hold a load, `rigHasOil`) and buyer are re-picked every trip. `chooseCompanyFor` is automatic unless the player stamped a buyer (`player.route`, action `setRoute`, the "Vozit sem" stamp on price cards, `buyerControls` hit rects; a closed buyer falls back to automatic): the best `quoteAtStock` after counting oil other vehicles already carry there, minus a distance term, and the owner's open contract wins. Trucks drive to `buyer.x`. Before the rail era they are horse wagons (`truckSpeed`, `WAGON_SPEED_MULT`). `moveTruckToward` never overshoots, `trafficLimitedStep` keeps gaps on the shared road.
- Town as the market (`BUYERS`, `world.market[id]`, `market.order`): Refinery `left`, Petrolejka `lamps`, Rail depot `right` (from the rail era), Benzinka `garage` (from the auto era). Roles: town shops pay the most but have small demand and saturate fast, the refinery is the big steady buyer, the rail depot exports with huge demand that never saturates (lower price, moved by world news); the distance term in `chooseCompanyFor` is deliberately small so price per barrel decides. Each buyer has `stock`, consumed at `demand` bbl/day (per era, scaled by player count on the shared map, `stepBuyers`); `price = base × noise × stockFactor(stock)` (a full warehouse pays less, `noise` is the seeded random walk in `stepMarket`), `quote = price × mult` (news) is paid, `closed` = not open yet or closed by news. Sales add to `stock` and `world.town.delivered`; crossing `eraThreshold` advances `town.era` (`ERAS`: camp, boomtown, rail, auto), opens buyers and emits `era`.
- Transport links (`network.link`, `buildLink`, `stepLinks`): a rig may have one `pipeline` (from `PIPELINE_ERA`, to any open buyer, cost per px of distance, `PIPELINE_RATE`) or `siding` (from `SIDING_ERA`, to the rail depot, flat `SIDING_COST`, `SIDING_RATE`). Oil flows from the rig tank straight to the buyer without trucks or strikes, paid `quote × LINK_PRICE_BONUS` (contracts apply, cartels break), batched into one `sale` event per `LINK_SALE_BATCH` barrels; the link pauses while the buyer holds `LINK_STOCK_DAYS` of stock, so it cannot crash a price. Trucks still take the surplus. Bots show links as a convenience, not a profit (`npm run balance links` ends ~20 % below `solo`): they replace flexible trucks with a fixed buyer and cost money up front; their value is no truck limit and immunity to strikes.
- Contracts (`world.contracts`, `stepContracts` on each day change, seeded by `contractRandom`): open buyers post `offers` (amount, fixed price, days); `acceptContract` moves one to `active` (max `MAX_ACTIVE_CONTRACTS` per player, first come on the shared map); deliveries to that buyer are paid the contract price (`applyContract`) and a missed deadline costs `CONTRACT_PENALTY` of the missing value.
- Shared-map diplomacy (all `world.shared` only): `buyPlot` opens an auction (`world.auctions`, `bid`, ends `AUCTION_MS` after the last bid in `stepAuctions`, the winner pays then or the claim stays free); `offerDeal`/`acceptDeal`/`declineDeal` move stored oil between players' rig tanks for a fixed price (`world.deals`, `moveOil`); `proposeCartel`/`joinCartel` is a pact not to deliver to one buyer (`world.cartel`, active once everyone joins, nothing enforces it: the first member who sells there triggers `cartel_broken` for all, `checkCartelBreach` in `sellLoad`); `sabotage` bribes a strike (`player.strikeMs`, trucks stand still in `stepTrucks`, the culprit is revealed with `STRIKE_TRACE_CHANCE`; events `sabotage`/`sabotage_over`, because `strike` is an oil strike).
- News (`NEWS`, `stepNews` on each day change): period headlines (1880–1910) that for some days multiply buyer prices (per buyer id or `all`), close a buyer (`<id>Closed`) or change rules (`taxMult`, `fineMult`, `truckSpeed` via `newsEffect`); `requires`/`minEra`/`maxEra` keep news out of the pool when its buyer or era is not there. Keep new headlines in period (no present-day politics).
- Overpressure (`stepPressure`): a pumping rig with full storage builds `pressure` (rules `pressureBuildMs`), vent action from `VENT_MIN`, at 1 a blowout (fine via `getBlowoutFine`, oil wasted, `plot.spill` grows). With enough trucks/silos it never blows out.
- Rules: `RULES.solo` vs harsher `RULES.race` (also used by the shared map), land tax per owned plot per day (`getLandTax`, grows monthly in survival mode), bankruptcy when money < 0, end after the race length or Dec 31 (`endPlayer`/`endAll`).

**Client bridge (`script.js`).** `world` is either local (solo/race: `restartGame(seed)` creates it; `raceMode` must be set first because it picks the rules) or a copy from the server (`startSharedWorld`/`applySharedSnapshot`). `syncFromWorld()` mirrors it into the old globals (`plots`, `money`, `trucks`, `leftIncPrice` = quote, `day`, ...) and computes the local player's view (`pocket.revealed`, `pocket.echoUntil`, `network.connectedPocket`, `hazard.visible`, `townEra`). Buyer cards read `world.market` directly. Input goes through `doAction(action)`: locally `OilSim.act` plus `handleWorldEvents`, on the shared map `Net.sendAction`. `myId` is `'player'` locally and the network id on the shared map; `isMine()` and `playerColor()` drive ownership-dependent drawing. `gameLoop` calls `update(frameMs * gameSpeed)` every frame unless paused; the frame delta is capped by `MAX_FRAME_MS` (an uncapped delta makes trucks overshoot and breaks the calendar). Purely visual effects (smoke, steam, gusher drops, fireworks, ambient life) are client-side and never touch the world.

**Network (`net.js`, `server/`).** `Net` boots on `DOMContentLoaded`: `GET /api/config`; in Discord (`frame_id` in the URL) `DiscordSDK.ready()` -> `authorize` -> `POST /api/token` (the server exchanges the code with the client secret) -> `authenticate`; elsewhere a guest identity, allowed only when not `NODE_ENV=production`. Then WebSocket `/api/ws` with `hello`; the server verifies Discord users via `/users/@me`. In Discord all API paths use the `/.proxy` prefix and the server strips it. If `/api/config` fails the game silently runs solo. `Net.openLink(url)` opens an external page (`openExternalLink` through the SDK in Discord, `window.open` elsewhere); it is used by the ads. Ads are configured only in `ads.js`: master switch `enabled` and the `ads` list (`url`, `banner` as [ink, red] parts). `pickAd()` (also honours the player's `prefs.ads`) draws a random ad with a banner, or null; the blimp picks one per flight (`blimpAd`) and tows it as a clickable banner sized to the text (`drawBlimpBanner`, `blimpHitRect`), without an ad it flies bare and is not clickable. There is no other ad placement. Currently one ad: the sibling project priceguessr.eu. The server serves only an allowlist (`/`, `script.js`, `net.js`, `sim.js`, `ads.js`, `style.css`, `img/`, `dist/`, `/fonts/<rye|courier-prime|barlow-condensed>/`), never the repo root; root files go through `sendFile(file, { root: ROOT })` so a checkout under a dot directory (a worktree in `.claude/worktrees/`) still serves.
- Rooms (`server/rooms.js`): one room per Discord `instanceId`, phases `lobby -> playing -> finished -> lobby`, the first connected player is host and only the host changes `settings` (`kind` race/shared, `mode` richest/target/survival, `target`, `months`) and can `start`/`reset`. Last standing ends a race when everyone else went bankrupt or disconnected (finishing on time does not count as out); `forceEnd` is the server-side timeout. Room logic is plain JS and is tested with fake `ws` objects (`{ readyState: 1, send() {} }`).
- Race (`kind: 'race'`): every client simulates its own world from the shared `seed`, sends `progress` every second and `finish` at the end; clients report their own money, so it is not cheat-proof.
- Shared map (`kind: 'shared'`, `server/shared.js`, max `MAX_SHARED_PLAYERS`): the server steps one world every 50 ms, applies rate-limited `action` messages, enforces target/last-standing and sends `snapshot` (rounded JSON + events) 5× per second, `shared_start` on start and on reconnect. Clients keep stepping their copy between snapshots for smooth movement (events of those local steps are ignored) and apply their own actions locally at once (`doAction`, optimistic; the next snapshot corrects). Snapshots are per player (`serializeFor`): pockets and hazards the player does not know arrive as `{ id, hidden: true }` without geometry, so `sim.js` guards on `vertices`/`hidden` in `findHitPocket`, `distanceToPocket`, links and tools, and nothing secret reaches devtools.

**Rendering (2.5D diorama).** Fixed 1600×900 logical world (`VIEW_W`/`VIEW_H`; never read `canvas.width` for layout) drawn on a canvas whose pixel size follows the screen (`resizeCanvasBacking`, capped at 2× DPR); `viewScale` is the base transform applied at the start of `draw()`, in `applyCameraTransform` and in `paintLayer`, and cached layers are backing-sized and drawn with `drawImage(layer, 0, 0, VIEW_W, VIEW_H)`. The canvas fills the 16:9 `#stage`. Logic stays 2D; only drawing fakes depth: `getGroundLevel()` is the front edge of a tilted surface slab (`slabXAt`/`traceSlabQuad`) with a town in the back, the road on the front strip, structures at `groundLevel - STRUCTURE_BASE_OFFSET`, and the underground cross-section below. Static layers are painted once through `paintLayer` (temporarily swaps the global `ctx`): `farCache` (sky and mountains with parallax; sky life follows the era: balloon in the camp, blimp from the rail era, biplane from the auto era), `claimsCache` (terrain of the claims on the slab: hill mound, river with a bridge over the road, boulders; keyed on `claimsStateKey()`), `sceneCache` (slab, town, road, rocks; repainted when `townEra` changes: `drawTown` keeps the same seeded slots for every era, a slot is born later the farther it is from the centre and its building type rises with age via `townSlotType` (tent → shack → house → brick → block), street, lamps, traffic and walkers also follow the era), `strataCache` (hatched rock layers as a geological section plus the granite caps of rock claims, repainted when `world.strata` or the claims change) and `townFrontCache` (houses in front of the main street, drawn after the walkers; `fitTownItemInFront` keeps their roofs below the sidewalk). The `camera` transform applies to the world; vignette, pause and game-over overlays are drawn in screen space. `getCanvasPosition()` returns world `x/y` plus raw canvas `px/py`, so hit tests work while zoomed. Plot signs show price, terrain and width; build previews show the terrain-adjusted cost (`plotBuildCost`). Side buyers (refinery, rail depot) have price cards at the edges, town buyers (`drawTownBuyerChip`) hang above their building with an unloading stand on the road. Hit rectangles for canvas controls (plot signs) are recomputed during drawing, so they exist only after a `draw()`. Known pockets are drawn as a cavity with an oil level at `1 − oil/maxOil` of the height (quarter marks on the wall, glow and bubbles only below the level). Pocket outlines are cached per `pocket.id` (`pocketShapes`) because shared worlds are replaced by every snapshot. Canvas text state leaks between draw functions, so set font/align/baseline before `fillText`. Sounds are synthesized (`SOUNDS`, no audio files).

**HUD.** HTML panels inside `#stage`, sized in `em` from `font-size: clamp(..., cqw, ...)` with a compact `@container` mode under 1200 px. Info panels (`#hud-goals`, `#hud-race`, `#hud-toasts`, `#hud-news`, `#hud-log`, `#news-flash`) have `pointer-events: none` so clicks reach the canvas. `#hud-map` is the geological survey sheet (`toggleSurveyMap`, key G, `#map-btn`): a second canvas painted by `drawSurveyMap` through the same `ctx` swap (`paintSurveyMap`, repainted every 400 ms while open) showing claims with terrain and price or owner stamp, strata hatching in ink, the player's known pockets, hazards, wells and a legend; clicking a claim buys it or selects its rig (`handleMapClick`). `#hud-players` (shared map only, toggled by `#players-btn` or P, `renderPlayersPanel`) lists rivals with stamp buttons for an oil offer, a cartel proposal and a bribed strike; incoming deals and cartel proposals appear in `#hud-contracts` with accept/decline stamps. Auction signs show the current bid, bidder and seconds left; clicking one bids `+max(25, 10 %)`. `#hud-contracts` (contract offers with an accept stamp and the player's running contracts, `renderContracts`) and `#hud-rig` (the drilling log of the selected rig, `renderRigPanel`) is clickable: its skeleton is rebuilt only when the layout key changes and values are patched every frame, so buttons survive mid-click. The rig log offers pipeline/siding buttons per open buyer (`linkCost`); links are drawn by `drawTransportLinks` (pipe on supports behind the rigs, rails with a shuttling tank car). Clicking an own rig: `bop` during a kick, `vent` on overpressure, otherwise it selects the rig (panel + drill preview with cost/time from `estimateDrill`). Overlays (lobby, results) only darken the scene, no blur, so the town stays visible. `updateUI()` runs every frame from `draw()`; use `setText`, which writes only on change. The first-game guide (`GUIDE_STEPS`, `renderGuide`, `#hud-guide`) runs only solo, advances when a step's `done()` holds, highlights the related button with `.guide-hl`, and is remembered as finished in `localStorage` (`oilDiggaGuideDone`) or disabled by the `guide` preference. On `warn`, `kick` and `blowout` of an own rig the camera focuses on it (`focusCameraOnPlot`, `cameraFocus`) and returns after `FOCUS_HOLD_MS` unless the player moved the camera (`cameraTouched`); the `focus` preference turns it off. Player preferences (`prefs`, `PREF_FIELDS`, `setPref`; sound, volume, camera shake, `life` (off = no sky life, town traffic, walkers, dust or random fireworks, so no blimp ad either, and ~40 % of particles), breaking-news overlay or a telegram instead, ads) are per-browser in `localStorage` (`oilDiggaPrefs`, read defensively by `loadPrefs`), never part of the world; the `#prefs` overlay is a pinned form sheet opened by `#prefs-btn` or the O key. Add a new preference as a `PREF_FIELDS` entry plus its effect in `setPref` or where it is read.

## Cache busting (Discord caches aggressively)

`index.html` sets `window.ASSET_VERSION = Date.now()` and loads `style.css`, the favicon, `dist/discord-sdk.js`, `ads.js`, `sim.js`, `net.js` and `script.js` through `document.write` with `?v=<version>`; images loaded from JS go through `assetUrl()`. Do not add plain `src`/`href` references to local assets. The server sends `Cache-Control: no-store` for everything. Fonts come from `@fontsource/*` packages (server routes `/fonts/<name>/`) because Discord's CSP blocks Google Fonts; canvas text needs `document.fonts.load` to trigger them (done in `initializeGame`).

## Git workflow used here

Work on a short-lived branch, commit with an English message, fast-forward merge into `main`, push `origin/main`, delete the branch (only when asked). Render deploys `main` automatically. Repo-local git identity is configured; do not change global git config. Never credit Claude or AI anywhere in git or on GitHub: no `Co-Authored-By` trailer, no "Generated with Claude Code" line, no Claude/AI mention as author or contributor in commit messages, PR titles or bodies, branch names or tags (`.claude/settings.json` turns off the automatic attribution too). `Analýza.docx` describes an older truck system and is out of date; trust the code. `CHANGELOG.md` is the player-facing history (see above). `docs/claude-code-prirucka.md` is a Czech guide to setting up Claude Code (plugins, token saving, self-made skills) for people working with Claude; it is not about the game.
